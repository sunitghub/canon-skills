# Agent Standards: domain notes

On demand, not always loaded. `efficiency.md` (always loaded) keeps the rules every session needs and names these sections in one index line; read a section before working in its domain. Moved here from efficiency.md in t-8837 (2026-10-15), verbatim.

## Duplication exceptions

The always-on rules are "same fact in several files → one owner" and "a third copy → remove the duplication". These are their two exceptions, which `tests/doc-mirror-parity.sh` and `tests/gate-model-parity.sh` rely on.

- Same fact in multiple files → pick one owner, derive the rest. Exception: deliberately-mirrored docs/prose that must stay self-contained for separate consumers (e.g. gate docs each dispatched to a fresh subagent) — keep the copies, lock them with a parity test (`tests/doc-mirror-parity.sh`) instead of merging.
- A third copy of the same logic appears → remove the duplication, don't copy again. Exception: same logic ported across incompatible runtimes (bash/Python/Go, etc.) with no shared-code option — keep the ports, lock them with a parity test instead of merging.

## Editing

- Inserting a block mid-file: check you aren't landing between an existing comment and the code it describes.
- Trimming a capped doc to fit its word cap keeps each clause's check, command and failure report: cut elsewhere or raise the cap, never hollow out an instruction (t-e75d; class: cap-trim-drops-instruction; id: P-047).
- A mass edit of lines whose `git blame` date a tool reads (promoted-report) lists its commits in `.git-blame-ignore-revs` in the same change; afterwards check the derived dates and counts on the real data (t-f74e; class: mass-edit-resets-blame; id: P-063).
- Before keying a default on a sentinel value (`=== null`), grep every writer of that state: a writer that stores another placeholder (`''`) means the default never runs (t-8be9; class: sentinel-not-written; id: P-070).
- An edit script that replaces text between markers asserts afterwards that every landmark of the file (function names, section headers) still appears exactly once: `bash -n` accepts a file with a whole block missing (t-29ee; class: marker-replace-deletes-block; id: P-084).
- A scripted edit (`str.replace`, `sed`) asserts its target matched exactly once and says so when it did not, and no edit is chained after a count: `grep -c` exits 1 on zero and short-circuits the `&&` (t-e9aa, t-9831; class: scripted-edit-silent-miss; id: P-098).
- After a scripted edit, re-read each changed line whole: on a dense one-liner every statement after the insertion point is still code (a trailing `//` swallowed the call after it, and every spec stayed green), and an insert into wrapped prose kept the wrap (t-9bc6, t-a18d; class: scripted-edit-damages-hit; id: P-137).

## Shell strict mode and traps

- Under `set -euo pipefail`, `VAR=$(cmd)` exits silently if `cmd` fails — `|| fallback` on the next line never runs. Safe: `VAR=$(cmd) || VAR=fallback` on one line.
- Under `pipefail`, `! cmd | grep -q x` can pass *without checking*: `grep -q` exits at the first match and SIGPIPEs the writer, so the pipeline reports non-zero even though it matched, and `!` flips that to success. It only fires when the writer still has output buffered, so a small input hides it and a larger one makes it deterministic. The same holds for `awk '…{exit}'` and `head`: let the reader open the file (`awk … file`), and test with an input larger than the pipe buffer (`t-fef7`, `t-4718`). Safe: `[ "$(cmd | grep -c x)" -eq 0 ]` — keep it inline; hoisting it to `n=$(cmd | grep -c x)` hits the previous trigger, since `grep -c` exits 1 on *zero* matches. A positive `cmd | grep -q x` fails the same way at random under load, which is why the full test run failed suites that passed alone; `tests/pipefail-early-exit.sh` refuses any `| grep -q`, `| head`, `| awk '…exit'` or `| sed '…q'` written on one line in a shell file under tools/, scripts/ or tests/ (`t-bcb8`, `t-ad89`). The rule: a reader that stops early needs a writer whose output is always small and bounded; otherwise let the reader open the file, capture first and match with `grep -q … <<<"$v"`, count with an inline `grep -c`, or end the line `|| true` when the kept value is the reader's own. A bounded writer goes in `tests/pipefail-early-exit-allow.txt` with the reason (matched on the line's text; a row that matches nothing fails). Not caught: a pipe split across lines, `| xargs grep -q`, `grep -m1`. `tests/pipefail-rewrites.sh` proves the rewrites on input over 64 KB.
- A bare `[[ cond ]] && cmd` as a function's LAST statement returns the `[[ ]]` test's own exit status (1) whenever `cond` is false — under `set -e`, that silently aborts the *caller*, not just skips `cmd`. Easy to miss because the common/expected case (`cond` usually true) never triggers it — it only fires once the false branch becomes reachable, potentially long after the line was written. Safe: wrap in `if`/`fi`, or append `; return 0` / `|| true` after it.
- Anything a function sets inside `$(func)` (an array append, a recorded PID) dies with the subshell, so a later cleanup trap kills nothing. Guard such helpers with `[[ $BASH_SUBSHELL == 0 ]]` (bash 3.2 has no `BASHPID`).
- Shell scripts: a function called in a `||`/`&&`/`if` list runs with `set -e` off, so an unchecked `mv`/`chmod` inside it cannot abort; `mv newdir olddir` onto an existing directory nests; `$((08))` is invalid octal (use `10#$n`). Make temp files with `mktemp` outside the work tree (or gitignore them) and remove them with `trap … EXIT`, not by a call on only the branch you tested.
- A child started under `set -m` (its own process group, so an interrupt can stop all of it) no longer gets the terminal's hangup: trap HUP with INT and TERM. Under `set -e` a trap's last cleanup command can fail (killing an already-dead group) and end the trap before its message: end each cleanup with `|| true`. A script backgrounded from a non-interactive shell inherits SIGINT ignored, so test an interrupt with TERM (`t-bad4`).
- bash 3.2 (macOS): `"${arr[@]}"` on an empty array is an unbound-variable error under `set -u`; use `${arr[@]+"${arr[@]}"}` (`t-1465`). A bare false `[[ … ]]` under `set -e` does not exit there either, so an assert written that way never fails: write `[[ … ]] || fail "…"` (`t-b62a`). `bash -n a b c` checks only `a` (`t-2633`).
- Concurrent `printf >> file` writers tear lines over about 1 KB: append a shared log with one write per line (Go `O_APPEND`) or under a lock (`t-f182`). A flag parser that reads `${2:-}` takes a trailing bare `--tokens` as "not given": check `$# -ge 2` and fail (`t-5ef3`).
- `IFS=$'\t' read a b c` collapses empty fields (tab is IFS whitespace) and shifts the rest: map empty to a placeholder upstream (`jq` `// "-"`) and test for the one expected value (`== false`), never `!= true` (t-a463; class: ifs-whitespace-collapses-empty; id: P-021).
- A line added to a script's ending (a message, a next step) is checked on every exit: each `return`/`exit`, the bootstrap path included (t-5738; class: every-exit-path; id: P-015).
- `"$d"/* "$d"/.[!.]*` misses names starting with `..`: a "folder holds only X" check built on it passes a folder with user data, then deletes it. Enumerate with `find "$d" -mindepth 1 -maxdepth 1` and plant a `..x` entry in the test (t-38ab; class: glob-misses-dotdot-names; id: P-049).
- `mktemp` + `mv` resets a file's mode to 0600: restore the original mode, or write in place (t-acfa). A command that rewrites a gitignored file with no other copy (DECISIONS.md) also keeps a `cp -p` copy until its self-check passes, refuses a non-regular target up front, checks every `mv`, and lets a line-count self-check tolerate a missing final newline (t-79bf; class: unbacked-file-rewrite; id: P-065).
- A sourced library's guarantee must not depend on the caller's `set -e`/`pipefail`: check each status itself and test it from a plain `bash` that sources it (t-3abc; class: lib-relies-on-caller-shell-opts; id: P-050).
- A helper that takes parameters as an env prefix (`GD_GROUP=x _gd …`) also reads them from the caller's environment: unset them at entry and test with them exported (t-d287).
- Never match `git`/`gh` human text (`Everything up-to-date`, `not found`) under the user's locale: run with `LC_ALL=C`, or use porcelain output or exit codes (t-10ac). A command that parses git output fixes every flag the repo's config can change (`diff.noprefix`, `diff.mnemonicPrefix`, `--no-ext-diff`, `--no-textconv`, `log.showRoot`, replace refs) and applies any cap after its filter (t-5988; class: git-output-config-dependent; id: P-097).
- Untrusted text goes to awk through `ENVIRON`, never `-v`: `-v` processes backslash escapes (`\n` splits a table row, `\|` vanishes) (t-8a0d; class: awk-v-escapes; id: P-069).
- A run started with `nohup` ignores SIGHUP and so do its children, so the HUP case in `tests/tkt-merge-pr.sh` fails: run stamps and timing drivers in the foreground (t-7e26, t-045f; class: inherited-ignored-signal; id: P-075).
- A comment inserted on a `[[ … ]] || fail "…"` line before the `|| fail` makes the `fail` part of the comment, and the bare `[[ ]]` never fails on bash 3.2: revert-prove any edited assertion line, and give a loosened bound a measured number, not slack (t-42ed; class: assert-line-edit-disarms; id: P-078).
- A shell client of a loopback service passes `curl --noproxy '*'` (an `http_proxy` in the environment otherwise routes it away) and pattern-checks any environment value before it enters a URL or arithmetic (digits, no leading zero, bounded length), both owned by one wrapper (t-ad6f; class: loopback-client-trusts-env; id: P-083).
- `$(…)` drops NUL bytes, so `[ -n "$(tail -c1 f)" ]` calls a NUL-ended file newline-ended: count with `tail -c1 f | wc -l`. macOS grep reads a NUL file as binary (no match) while Git Bash's GNU grep matches: plant a NUL byte in the fixture (t-d8af; class: nul-dropped-by-subst; id: P-095).
- A shell function named like a command makes `command -v name` print the bare word (a self-link when it builds a PATH dir): resolve the file with `type -P name` (t-fff4; class: function-shadows-command-v; id: P-096).

## Tests, guards and hermetic runs

- A test failing inside a block your diff touches is not automatically pre-existing/unrelated — diff its failing assertion and target string against the base commit byte-for-byte before excluding it from scope.
- Grade test-count/pass-rate claims (e.g. "121/121 pass") against the actual recomputed total from real command output, not the doc's own summary arithmetic — check specifically for a silently-omitted did-not-run set. Quote a timing only from a run that exited 0 with every suite run (`t-b792`); before cutting tests for speed, measure time per suite (`scripts/test.sh` prints it) and check each "duplicate" an inventory flags against the code, since most tested different behaviour (`t-dd2f`).
- A test asserts against a re-implementation of the logic under test → call the production function instead. A locally rebuilt sort key or a hand-copied constant list passes while the real thing is broken. The same holds for a gate: compare against the real writers' output (replay them), not a copy of their format (`t-52f0`). A check that normalises (indentation, order) cannot see a bug in that dimension: pair it with an exact check on what must not change, and mutate each (`t-565f`). Nor is the expected value produced by the code under test: a CLI's output compared with the printer it calls cannot see what the printer drops; assert rows from the source data (t-ffa8; class: oracle-is-code-under-test; id: P-148).
- A guard exercised only against inputs it already handles is unverified → feed it the cases it must *reject*. Include spellings it has not seen; a match inside a comment does not count. A guard over a list (triggers, patterns) is tested by deleting each entry in turn; a "nothing reads/uses X" scan is proven by planted readers in each spelling (`$ROOT/…`, a variable dir, a JS path) (`t-278d`, `t-0b14`). An OR'd rule is such a list: plant one case per clause and mutate each clause, not only the field name (t-ca5b; class: or-clause-unguarded; id: P-088). A "something emits X" scan matches the emit call (`canon_event X`), never the kind's name, which every reader also names (t-bcc1; class: emit-scan-matches-readers; id: P-089). A "nothing left behind" check (process, file, port) must observe what can leak (record the pid and `kill -0` it): an `lsof` on a stub that never listens passes. Prove it with a mutant that leaks. A test that starts a real daemon session ends it in its own teardown: a leftover live session fails the next test, which then passes alone and reads as a flake (t-3e06; class: test-leaks-live-session; id: P-087). An absence assertion (`toHaveCount(0)`, "no dialog appeared", "never sends X") is revert-proven: a poll can clear the thing for you, a process-name watch subtracts what is resident (CoreServicesUIAgent), and "never sends" needs a spy on the receiving page (t-a1ac, t-3488, t-2aed; class: vacuous-absence-assertion; id: P-036). A per-line exemption marker (`/* non-ticket */`) needs a mechanical reject, not trust: the lint fails a marked line that names the guarded thing, and its probes include a marker on a forbidden line and an unlisted spelling (`"t-" + Date.now()`) (`t-eb92`). On macOS `mktemp -d` with no template ignores `TMPDIR`, so a temp-file leak check that pins `TMPDIR` watches an empty directory: give the code a template (`mktemp -d "${TMPDIR:-/tmp}/x.XXXXXX"`). A self-checking guard prints the counter it keeps, never a hardcoded count (`t-b525`).
- A stub must evaluate its input the way the real tool does (a fake `python` that exits 1 on any code hides a dropped version test) and have a mode for each branch the code takes, the fallback included; a stub that returns already-processed output (a `gh` stub returning TSV) never runs the real query or `jq`, so back it with one live read-only run. A per-candidate timeout bounds the wait for one candidate only: two hanging candidates take twice as long (`t-a5f6`, `t-1465`, `t-4cd8`). In a PATH dir of symlinks to real tools, put stubs first and skip their names when linking: `cp` onto a link writes through it into the real binary (`t-90a3`). A stub that is a silent `exit 0` cannot prove a call or its order: record each call and assert the sequence (`t-2ea4`).
- Where PID 1 does not reap orphans (a Claude cloud container), `kill -0` answers alive for a zombie: count a zombie as dead (`ps -o stat=`), falling back to `kill -0` where `ps` has no `-o` (`t-90bc`). Code that runs in a sandbox is tested under the sandbox's limits: a Claude cloud session's GitHub proxy allows REST only, so cloud-side `gh` calls are `gh api` and the test stub refuses GraphQL and the network on that side (`t-35d2`).
- Writing a parser or a gate for an existing artifact family (reports, tickets, logs) → count the shapes across all real instances and read the producer's own template first; run it on a real instance, not only fixtures shaped like the parser. A filter that drops boilerplate must name the boilerplate, not whitelist one content shape (keeping only list items dropped table sections); a line filter over Markdown (`# `, `<!--`, `## `) tracks code fences and position, with one fence rule on both sides of a round trip. Test it against every section shape real files use (lists, tables, prose, fenced code), and test a reader with the writer's real output (`t-a059`, `t-8543`, `t-554c`). A second reader of a field reuses the first reader's normalisation (strip bold: `**YES**`) instead of parsing the raw word (`t-f13a`). A log reader counts what the log means (one run per `agent_id`), not lines, and reads each per-ticket file once (t-b874; class: log-reader-counts-lines; id: P-023). This holds when an existing report-only reader starts gating: re-count the shapes real reports use (`GAPS: three findings` was refused as "has not run") (t-2bfe; class: lax-reader-becomes-gate; id: P-142).
- New security/validation/race guard → ship a test that fails when the guard is reverted, and run the revert. Two causes for one symptom → prove each fix necessary by reverting it alone, plus one end-to-end test through the real client path. A revert counts only if the mutant ran and failed on its own assertion (a mutant that exits on setup, such as no manifest or a fresh clone running 0 tests, is no kill: read the counts; mutate a measurement fixture before baselining with it) (t-d689, t-3741, t-4fbe; class: mutant-killed-by-setup; id: P-025). Redundant layers mask a lone revert, so test each layer separately. Each reject fixture is otherwise valid (real hash, real ids) and breaks only the clause under test, so every clause has an input only it rejects; disable the siblings to prove one guard, and N claimed layers need N revert tests (t-4371, t-3741, t-2af0, t-2aed, t-c6bb; class: guard-masked-by-sibling-check; id: P-019). A mask or bit-test guard needs a fixture on each side (0750 and 0755, not only 0755), and platform-gated code is mutation-swept on each platform, since a sweep on one never reaches the other's branches (`t-68ae`). Run reverts only in a scratch copy, never on tracked files. A fixture equal to the default the code would produce anyway (mode 0600 from `mkstemp`) cannot fail on revert. A "no leak" test of an environment pin also asserts the values that must pass through (`GOMODCACHE`), not only the absence of the pinned ones (`t-eb40`). A race fix needs a stress loop (dozens of trials) plus a deterministic test that holds the lock; a read-then-append on a shared file is check-then-act, so lock the pair.
- A green run where something didn't run proves nothing → treat "command not found", a silent skip, an early exit hidden behind a `grep` filter, or a test file missing from the entrypoint as a failure.
- A suite that reads committed HEAD (`evidence.sh scope-audit`, `tests/release-zip-slim.sh` builds from the tree's commit) cannot see the staged change, so the pre-commit run passes a commit that breaks the next one, and a staged fix of HEAD cannot pass its own hook (t-2912: a new shipped file went over the zip cap; a message line tripped scope-audit, landed with `--no-verify` on the user's OK). Run such suites again right after the commit lands (t-2912; class: check-reads-head-not-index).
- Git config leaks into tests → pin `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM` and `XDG_CONFIG_HOME`. Worktrees share one hooks directory, so a hook finds its checkout with `git rev-parse --show-toplevel`, never from its own path. Ignore a symlink without a trailing slash (`/x/` matches directories only). Pin `HOME`, `TMPDIR`, `XDG_*`, `CANON_HOME` and any variable a wrapper exports (`CANON_TICKETS_DIR` from `evidence.sh`) too, and reproduce a "passes only on my machine" test under `env -i` or `scripts/test-hermetic.sh`. A test that guards a locale bug pins `LC_ALL` to a UTF-8 locale, or the bug hides when the suite runs without one (t-a811; class: locale-unpinned; id: P-094). A test of delete/kill code plants a canary in the pinned dirs. A test that runs git in a temp dir unsets `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`: a hook hands them down, and `GIT_DIR` only from a linked worktree; a hook cleans only the child it starts. A test that writes under its own root runs on a scratch copy with a canary (`t-1cfc`, `t-ce0b`, `t-65c9`). A fake `https://github.com/...` origin rewrites reads (`ls-remote`, `fetch`) as well as pushes, and `scripts/test.sh` exports `GIT_TERMINAL_PROMPT=0` (t-9791; class: test-reaches-real-network; id: P-034).
- A fixture named for a kind (a worktree, a CRLF file, a subfolder project) is a real one (`git worktree add`, not a plain folder); git-aware code is tested from a linked worktree and from a project subdirectory, and asks the caller's worktree, not the main checkout (`t-21f7`, `t-1b74`). Put the check in the command, not the UI, so the Terminal and the dialog cannot disagree (t-ced8; class: check-runs-in-wrong-checkout; id: P-012). A `tkt land` close has two roots: the ticket folder is the main checkout's (`project_root`) while the commit under review is the worktree's, so a HEAD read after `cd "$root"` grades main; test land-mode code from a real land worktree (t-f8e9; class: land-two-roots; id: P-138).
- Changing a test's expected value to match new code → name which user's answer changed; if it is the common case, it is a regression (`t-12f8`).
- A test wait that hits its deadline fails loudly rather than continuing, and a "no new flakes" criterion needs a run on the base commit first (`-race` was already red on main) (`t-67a6`). A narrowed or deferred browser run (cloud chromium only, no WebKit) leaves its criterion unproven, and a flake claim needs enough base and branch trials to tell the two apart (0/2 against 1/2 does not): the Mac full-spec run is the gate (`t-9a49`). A tool reported missing is not a blocker until its install fails (`npx playwright install webkit` took 6 s) (t-16ce; class: missing-tool-deferred-untried; id: P-093). Measure the cause before adding a retry or loosening a guard (31 of 31 retried stalls stalled again), and classify a baseline entry from its logged error, not its test title (`t-8627`). A failure that also fails on the base or on every dev checkout is a dependence (real data, root, an unscoped selector), not a flake: read its message and ask the environment before baselining it (t-cca5, t-432d, t-6fb8, t-d0a5; class: misdiagnosed-flake; id: P-024).
- Write assertions that can see the bug: a command that publishes is checked against the source of truth (origin's merged head), not the local copy; a captured exit code is asserted with the output; an event test asserts right after the transition that must cause it, and that the event is absent before (`t-24b1`, `t-1cf5`, `t-8854`). Choose inputs where the broken answer differs from the right one: ids that sort differently from the order under test, a stale cached value unlike the fresh one (the cache key names everything the value depends on), a look-alike name and a mode-only change for an allow-list, a width where the share exceeds the cap; a refusal test checks the body and that no file changed, not only the status (t-a5c9, t-7456, t-75f5, t-1bd5, t-0ef2; class: fixture-cannot-distinguish-mutant; id: P-017). A pick of one event among many (the first `close.started`, the last reviewer `gate.finished`, only the `ran` row) gets two of each plus a decoy of the neighbouring kind (t-0abe; class: pick-fixture-one-of-each; id: P-090). A restore or rewrite asserts the exact position, not "present under some heading" (t-e790, t-dde9; class: position-unasserted; id: P-091). An assertion that accepts either of two outcomes cannot pin the one a guard decides: move the choice into a pure function and check it exactly, and test each half of an "or" criterion (hover or focus) on its own (t-a7e0; class: either-outcome-assertion; id: P-092).
- A test that locks wording anchors each phrase to the line that prints it (echo, die, throw), not help text or comments, and asserts every clause, verb and condition included; a mutant removes or flips exactly one fact (`t-153f`, `t-ce0b`, `t-1cf4`).
- A new ignore rule for a path that may already be tracked: `git rm --cached` it, and add a check that fails when a tracked path matches (`git ls-files -ci --exclude-standard`) (`t-fc00`).
- A test that reads source text (greps a file for a branch, slices a page between two literal lines, counts colours per file) is a reader of that text: grep `tests/` before replacing or moving a line, scope the search to the handler it guards with comments stripped, and count the real thing (`len(actions) == 0`), not a typed copy of today's 8 (t-6aaf, t-bb1b, t-be64; class: source-grep-test-fragility; id: P-032).
- Tests that copy a fixed list of files or tools into a fake install break when a launcher sources a new sibling or a tool joins `tools/`: give the list one owner in `tests/helpers.sh`, or grep `tests/` for copies before adding a file the launcher loads (t-b2ff, t-187e; class: fixed-file-list-in-test-fixture; id: P-016).
- A runner that globs its output folder for reports clears it first or refuses a non-empty one: a reused `--out` kept an earlier run's reports for the guard to judge (t-43a2; class: stale-output-dir; id: P-033).
- A before/after trial proves a fix only if the before run shows the symptom; if it does not, the criterion is unproven: say so, never count it as passed (t-e115, t-39a8; class: trial-without-control; id: P-056). A gate replay is scored by hand against a real defect fixed later, never by its catch regex alone: the regex missed real finds and matched a passing row by accident (t-b809; class: replay-scored-by-regex; id: P-135).
- "Tracked or ignored" is read from committed state (`git ls-files`, `git cat-file -e HEAD:<path>`), never `git check-ignore` (also reads `info/exclude` and the global excludes) or `ls-files --error-unmatch` (reads the index: staged-only, `--assume-unchanged` and `--skip-worktree` pass); test with a local-only ignore and a staged-only file (t-43a7, t-c91a; class: local-vs-committed-git-state; id: P-051).
- A linked worktree is `--git-dir` ≠ `--git-common-dir`, never "`.git` is a file" (a submodule has one) or "the common dir is named `.git`"; test from a submodule and a `--separate-git-dir` repo. A linked worktree's `info/exclude` is repo-wide (t-74d8, t-2db7).
- A test of a local-clock time never assumes a fixed hour gap (DST shifts it): compute the expected value with the same clock call, or pin `TZ=UTC` (t-11e6).
- A unit test never runs the real OS auth (`dscl -authonly`, `su`, `sudo`/UAC): inject the auth hook, and run the real one only in a named manual check (t-353a).
- A new per-machine runtime file under `.tickets/<id>/` joins the `.tickets/.gitignore` seed (`tools/tkt`) and the `docs/setup.md` list in the same change (t-10ac).
- A test that writes through code with a retention or prune (the board's event log) pins the clock that code reads (`CANON_EVENTS_CLOCK`), or the first write prunes a fixture dated weeks ago (t-7e26; class: fixture-pruned-by-retention; id: P-074).
- A check that needs a rule another tool owns (freshness, a section or bullet parse) calls the owner (`evidence.sh neutral`, `_acceptance_section`), and its test runs every form the owner accepts through the new reader (t-aa24, t-51c6; class: reimplemented-owner-rule; id: P-077). It reads the same occurrence the owner reads (the first `## Sign-off`): a reader that took `Tier:` from any Sign-off released the evaluator with no review (t-a4e8; class: reader-reads-other-occurrence; id: P-141).
- A new warning is tested in every case where it must stay silent, not only the one that fires; when it must go to stderr the test reads the streams separately, because `2>&1` cannot see a dropped `>&2` (t-6be7, t-c923; class: warning-quiet-and-stream-unpinned; id: P-079).
- A test that loops over rows and `continue`s past those that do not match counts the matched rows and fails unless the count is the expected one: a renamed key otherwise passes with zero rows checked (t-70f2; class: filter-loop-vacuous; id: P-082).
- Compare numbers as numbers (`-eq`, `(( ))`), never as strings: a fixture line that embeds the temp path changes the string's length per machine; run a changed test once under a long `TMPDIR` (t-8d45; class: numeric-compared-as-string; id: P-085).
- A seen-set or cycle guard is tested with a cycle that does not pass through the start (lead-in X → Y → Z → Y), and its test runs under a short `-timeout` so a broken guard fails instead of hanging (t-f094; class: cycle-guard-lead-in-untested; id: P-139).
- A parity pin between two lists states its direction and checks both (A ⊆ B and B ⊆ A, or equal sets): asserting only that every `--list` label is parsed let an invented label pass (t-ef9c; class: one-way-parity-pin; id: P-143).
- A selector that maps paths to rules (the suite map) fails safe per path, not per run (a path whose row selects nothing forces the full run), and is asserted against the project's real map, not only a fixture map (t-2912, t-0fe6; class: selector-drops-path; id: P-147).

## Security checks and gates

- A hostile-input test must match the sink's context: escaped text in `title="…"` needs a quote-breakout payload (`a"onmouseover="x`), not just `<img onerror>`.
- Widening what a security check allows → re-validate the new value at the point of use; never lean on an earlier check you haven't read, especially for files an agent can write (`.tickets/`). A flag that supplies a fact (`--pr N`) still passes the check that fact stood for (the ticket was imported): the check reads the ticket, not the flag. An allow-list of names admits by name only, so also check the type (a symlink under an allowed name), scope it to the one subject (`.tickets/<id>/`), and refuse dotfile parts (`t-c259`, `t-fdb1`). A check made only when data is saved does not protect a later reader: re-check at the point of use (an API key must not go to a hand-edited source host), and a load, slow call, save handler re-loads before the write or it overwrites changes made meanwhile (`t-d40b`). The converse: check saved user data's shape at save and its validity against the live registry at use, or a moved registry refuses unrelated saves; a migration that carries a pick into a new shape runs it through the new rules (t-f5fa, t-8f6d; class: save-revalidates-moved-registry; id: P-104).
- A new check that verifies what an older gate accepts must read every line the gate reads (every `^pass:`, not `head -1`), or an extra line walks past it.
- A guard that fails closed then falls through → check what the fall-through *writes*: a transient error (git, network) must not overwrite the state the guard protects. Pin it with a file-content assertion.
- An error must not become a normal-looking result: a failed read is not "absent", a failed `git` call is not "not a repo", and `curl` without `-f` prints an error page as output. Match the one error you expect; let every other one fail. A selection picks the top by the real metric, then validates it and drops the whole answer: skipping an invalid top for the runner-up turns "unknown" into a guess (t-b6ad; class: skip-invalid-keeps-runner-up; id: P-105).
- Text from a clone, an issue or a pushed branch is untrusted input to a local command: validate any id before building a path from it, refuse to write through symlinks under the target, and check repo visibility before pushing notes. When a filter admits untrusted input (a label), take the admission fact and the content from one read: a label check then a second body fetch is a TOCTOU gap. A new reader of PR content checks fork origin before it fetches, and asks about the same repo it fetches from (the ticket's `github:` repo vs `origin`) (t-07b5; class: untrusted-pr-head-read; id: P-035). Strip C0, DEL and UTF-8 C1 control bytes from anything echoed (`t-554c`, `t-4cd8`). Refuse input a parser could misread (a log name `z exit=0 y.log`) rather than parsing around it (`t-a3d7`). A message handler ignores a malformed value; it never coerces it to a default (t-7456; class: handler-coerces-malformed-input; id: P-020).
- Running a project's tests on a PR is running the PR's code: ask before it, and take the test command from the base branch so the PR cannot switch its own gate off. For an irreversible action, re-check the outcome on failure (`gh` can error after GitHub merged) (`t-4718`). Write the record of an irreversible action right after it, before any step that can fail under `set -e`: moving the write later makes every unguarded command in between a way to lose it (t-41ff; class: set-e-skips-post-irreversible-write; id: P-031).
- A pin covers only the file it names: the docs it loads read other paths, and `claude -p` still loads the PR checkout's own `.claude/settings.json`, `CLAUDE.md` and `.claude/skills/`. List what the pinned file loads before calling the PR's code pinned (`t-89b0`).
- Granting `git diff` or `git log` under dontAsk lets `--output=<file>` (and abbreviations such as `--outp=`) write any file: grant read-only git only through `tools/git-read`, and grep the tree for any other plain `Bash(git diff:*)` grant (`t-5ff5`; detail in `docs/headless-ci.md`).
- A new gate rule that names a finding states its condition next to the rule and is reconciled with the gate's exclusion and scope sections (`## Do Not Flag`, `## Scope` in `skills/wrapup/gates/security-review.md`) in the same edit: a rule naming unpinned actions as a finding collided with that gate's own "no hardening" exclusion (`t-fcb3`).
- Put a gate where every route passes (a hook), not in one command, and list the routes around it (push by URL, a child that reads the hook's stdin). A guard that cannot run (script missing, older checkout) refuses, and it judges the commit being published, not the working tree (`t-4ea4`, `t-b6b6`).
- Before tightening a shared escaper, list callers that escape a whole document and then parse it (`md()`'s image pass), and decode what they extract; a "none left" sweep searches the whole pattern, not only the same-expression form (`t-d2e1`). Filter the parsed result (`md()`'s output in an inert `<template>`), not its source or an output regex: transforms in between bypass both (t-c6bb; class: sanitize-at-wrong-layer; id: P-029).
- Before publishing, look at every image (blurs leak a private tab); a guard that bans a string builds it from parts, so the guard file does not reintroduce it (`t-afe2`).
- File names from a list, a PR or a user reach git as pathspecs: pass `--literal-pathspecs` (or `:(literal)`) to `add`, `checkout` and `rm`, and check no parent folder is a symlink before deleting (t-32f9, t-41ff; class: git-pathspec-from-data; id: P-018).
- Docs and acceptance state a mechanism's limit (a keyless chain detects a changed middle line, not a removed newest one) and claim "verified" only for what was run (t-3137, t-3488; class: security-claim-overstated; id: P-030).
- An audit line records only what the emitter can know: leave `actor` absent on a route a local script can drive (token-free, or empty Origin accepted), and let the viewer say unknown (t-4c09; class: audit-log-overclaims-actor; id: P-009).
- A command printed for the user to paste quotes every argument for the shell (single quotes with `'\''`, or `printf %q`), never raw inside `"…"`; run the printed line in a shell with names holding a space, `$`, a backtick, `"`, `'` and `!` (t-11e6; class: pasted-command-injection; id: P-052).
- Path containment is never a string prefix: `case $t in $ROOT/*` admits `$ROOT/../x`, and Go `HasPrefix(rel, "..")` refuses `..foo`. Resolve first (`realpath`, `filepath.Rel` then `rel == ".." || HasPrefix(rel, "../")`), through the filesystem (`cd -P`, `-ef`), never by popping `..` as text before symlinks are followed; test `..`, `..foo`, `link/nx/../..` and a symlinked parent (t-38ab, t-f5e4, t-9fb1; class: containment-by-string; id: P-048).
- File names derived from data go after `--` for any command, not only git (`--list` is an option otherwise) (t-cc88).
- A GitHub list read (`per_page=100`) paginates, or treats a full page as "maybe more" and says so; a truncated list never answers "none" (t-4b34).
- A guard keeps its state where the guarded caller cannot move it: a registry under the caller's `TMPDIR` is invisible to a gate that pins its own. A file a gate script sources joins `scripts/integrity-list.sh` `GATE_FILES` (t-b7df).
- A command that gains a write drops every "read-only" label it carries: help text, header comment, docs, and any allow-list that runs it unconfirmed (`term.go` `readOnlyTkt`) (t-c990, t-7c89; class: stale-readonly-label; id: P-055).
- A reader of any path under a repo-controlled tree (`.tickets/`) Lstats it, reads regular files only, caps the size and opens with O_NONBLOCK, so a symlink is never followed and a FIFO never hangs the route. Adding a route: grep for bare `os.ReadFile` on repo paths; test with a symlink, a FIFO and a cap+1 file (t-ca73; class: repo-path-read-unguarded; id: P-060).
- When a gate prompt's required label list changes, the shape check keeps accepting reports already written to the old list (choose the list by the labels a report starts with); run the check over every existing report before and after: 0 differences (t-0ca2; class: format-change-breaks-old-artifacts; id: P-064).
- Text made safe for display (`tr -c '[:print:]' '?'`, a length cap) is a display copy: anything sent back as a key (an ignore list, a path to act on) carries the raw value or an index. Test with a non-ASCII name and one over the cap (t-a854; class: display-copy-used-as-key; id: P-073).
- A check that can switch a gate off reads its own scope (the gate-file list, the tier) from the base (`git show <base>:<path>`), parses it with the owner's parser, diffs with `--no-renames`, and needs each list non-empty on its own; probe delete, rename and editing the list in the same change (t-51c6; class: gate-scope-from-editable-tree; id: P-076). Any check that classifies changed paths (records only, docs only) reads them with `--no-renames`: rename detection shows only a moved file's new path, so code moved into the class passes as the class (t-7db9; class: rename-hides-source-path; id: P-103).
- A guard that compares a value with one derived from the same source is a tautology (base from the checked-out branch cannot refuse "another branch"): take the base from the default branch (`origin/HEAD`) and test from a checkout on another branch (t-8990; class: guard-base-from-head; id: P-099).
- A unified-diff parser reads file headers only before the first `@@`: skipping every `+++ ` line also skips an added line whose text starts `++ `. Check the parsed count against `--numstat` and plant a `++ x` line (t-7d84; class: diff-header-skip-bypass; id: P-100).
- A security check that runs only on a schedule lets a release ship a known-vulnerable pin between runs: run the same check as a release refusal, so the release path owns the freshness (t-d600; class: scheduled-only-check; id: P-101).
- `git hash-object --stdin-paths` (and any `--stdin` path list) reads a line starting with `"` as a C-quoted name: refuse such names as you refuse tab and newline, and probe `"a"` and `"b` (t-eeb5; class: stdin-path-c-quoted; id: P-102).
- A "never X" rule (never exclude G112) gets a check that refuses X, proven by planting X: a rule stated only in the file, the doc and the criteria is not a guard, and the plant that proves the guarded check goes green once X is allowed (t-9a2b; class: doc-only-rule; id: P-146).

## Destructive commands and user files

- Async lookup before a destructive action → after the `await`, re-check every precondition (identity, status, liveness), not just the one you guarded; test it by gating the request.
- Command that deletes data or stops processes → its "nothing unsaved" guard lists everywhere git keeps work (dirty tree, unpushed commits on every branch, stash, linked worktrees, skip-worktree edits) and probes each; it refuses when run inside the process it would stop; a prompt between probe and signal is an `await`, so re-verify identity at the signal. Test every rejected spelling.
- Before an irreversible delete, check the keep-rule against the shapes real data uses (docs cite evidence as a folder or a wildcard, not only a path): a dry run that shares the real run's rule cannot reveal that rule's gaps. A "nothing else was lost" claim comes from checking every affected item, not from one search pattern (`t-2fb6`).
- Editing a user-owned structured file (JSON/TOML) with `sed`/`awk` → guard the invariant, not the patterns: a signature of everything outside the edited member plus a validity check, and restore the original on any difference. A managed-block edit (BEGIN/END markers) changes only lines between them, matches the markers with a trailing `\r` stripped, and says "added" only when the file changed; its tests include a user line outside the block and a CRLF file (`t-5c4b`). A prune outside the markers recognises only canon's own exact lines, never a pattern (`@*/standards/*.md`) that a user's import also matches (t-351c; class: prune-matches-user-lookalike; id: P-028).
- Never `pkill`/`kill` by matching a process name, script path, or command-line pattern shared with anything the user might independently be running (a dev server, an agent daemon, a shared script invoked from elsewhere) — a pattern match can hit the user's own live, unrelated process and kill in-progress work with no undo. Resolve the exact PID first (a lockfile/state-file's recorded PID, the port a service publishes, or `$!` from a process this session itself started) and kill only that PID.
- A list that feeds a delete never emits a path built from an empty substitution (a failed `cygpath` turned `$(cygpath -u …)/canon-cockpit` into `/canon-cockpit`): skip the entry when the conversion fails, and test that failure (t-4872; class: empty-substitution-in-delete-path; id: P-014).
- A merge resolver for a canon-managed file resolves only canon's own block: it refuses when text outside the block conflicts, keeps every non-row line inside it, and dedupes by row key (ticket id), not the whole line, so a status change on one side cannot bring back the old row. A commit labelled as canon's record diffs each file and refuses hunks that are not canon's own fields; "the file changed" is not that check (t-27bc; class: resolver-widens-scope; id: P-054).
- Fix text that names something to delete names the narrowest offender (`.claude/skills/<name>`), never a folder kept because it holds user files; a test asserts the exact path (t-38ab).
- Mutants and any destructive cleanup (`git checkout .`, `rm`) run from a script file that `cd`s into the scratch clone and refuses any other directory, never from a chained one-liner: under zsh the chain broke before the `cd` and `git checkout .` reverted the real tree (t-2a21; class: destructive-command-wrong-cwd; id: P-106).
- A multi-step command that writes before its last refusable step either writes last or restores on every abort, and its "nothing changed" message is true on each path (t-6555; class: partial-write-on-abort; id: P-107).
- A preview (`--check`, a dry run) that a later run acts on pins what it showed (origin's tip, the file list), and the run acts on that pin or refuses if it moved; both share one skip rule and one tree read, or `--check` says ready while `--yes` refuses after its own side effect (t-420c, t-a01e; class: preview-run-diverge; id: P-108).

## Renames and doc sweeps

- Moving, changing the contract of, retiring or renaming a file or mechanism → sweep every doc surface by concept and paraphrase (cross-references, anchors, README prose, other skills), not only the known phrase; an exact-phrase grep proves only known spots; for a "nothing else" or "already in docs" claim, state the search scope and run it unrestricted (`git grep`, no file-type globs) and recompute counts. A rename by string also hits identifiers that only share the prefix: classify each hit, list the kept ones in `acceptance.md`, and exclude exactly that list from the evidence grep. A doc claim about a UI or a tool's flow is checked against the surface the reader sees (render it) and the tool's own printed next step (`t-e6d2`). An inventory of "every way X happens" searches by capability (every way a process or remote session starts) and names its patterns in the file (t-d42a); review a global `sed` per touched file (t-0aa7; class: inventory-by-pattern-incomplete; id: P-022).
- Before renaming a field to match a plan, read what its published contract promises (`docs/plugins.md`: v1 only gains fields); add the new thing as an optional field instead (t-15b5; class: breaks-published-contract; id: P-011).
- A command's printed line is a contract: before rewording it, `git grep` `tools/` for readers that match it (a `/^Local [^:]+: /` regex, a `tkt finish` substring), and feed each reader the real output in a test, not a stub (t-e7fb, t-607a; class: printed-text-has-readers; id: P-053).
- The same holds when a value gets longer: grep every writer's length limit (an event field's cap) and every reader's cut and allowed-character filter (`safe()`, the 80-character display) (t-0317; class: grown-value-truncated; id: P-080).
- Adding a member to an enumerated set (a gate role, an event kind, a Sign-off field) → grep every reader of the whole stream, not only the set's literal: a new role broke a reader that took the first `gate.started` as the start of the gates phase (t-9b13, t-864c; class: new-member-old-reader; id: P-113).

## Cross-backend parity

- Cross-backend equality: parse JSON before comparing (`json.dumps` vs `json.Marshal` differ in whitespace); compare bytes only for files. Aim parity fixtures at text edges (trim sets: Go `strings.TrimSpace` strips NBSP where the shell's exact compare keeps it, so trim ASCII only and plant `value<NBSP>`; lone surrogates, invalid UTF-8). For a user-edited file also use valid-but-wrong shapes (`null`, array, scalar), and CR/CRLF: run one hostile line through both ports (bash stripped every CR, PowerShell only trailing ones). A rule that must hold in N implementations or N lists gets one case table run through all of them, each fixture bare for the case under test (a home with `.git` hid a started-in-home bug); two sides naming one folder derive it from the same call, and a guard that byte-compares a writer's output runs under the setting that changes bytes (`core.autocrlf=true`) (t-dec4, t-5738, t-4872, t-b266, t-cb66, t-c2de; class: parallel-ports-drift; id: P-026).
- A migration one reader runs in memory (Go `FillNewSteps`) does not reach another reader of the same file (a markdown protocol reading the registry JSON): give each new key its fallback in every reader, or write the migration to disk (t-9b13; class: migration-reaches-one-reader; id: P-114).

## Platforms

canon runs on four: every session's AGENTS.md carries a one-line pointer here (tools/skills/agents.sh, t-5c4b).

- **Windows: the `.cmd` shims from any shell, `.sh` scripts in Git Bash.** canon's commands (sprint, tkt, skills, canon) run from PowerShell, cmd or Git Bash through their `.cmd` shims, which start Git Bash (Copilot CLI's shell on Windows is PowerShell, t-fcb1); a `.sh` script runs only in Git Bash. Run them exactly as written: never pipe one into head, `Select-Object -First`, a pager or a filter, and never drop its output, because the output is the next step and a reader that stops early can stop the command partway.
  The Bash tool is Git Bash: unquoted `C:\...` backslashes are escapes (and trip Claude Code's approval prompt). Use forward-slash (`/c/Users/...`) or quoted paths. A suite that has only run on macOS hides host assumptions (real `uname`, `python3`): tests that model a platform stub it (`uname`, `cygpath`), and a skip must be loud. Git Bash spells one directory two ways (`/tmp/x` vs `C:/…/x`): never compare a shell path with a git path or `gitdir:` pointer as strings; use `git rev-parse --show-prefix` and test with a stub that spells it the Windows way.
- **Paths: one folder has several spellings** (macOS `/var` and `/private/var`; Windows `C:\x`, `C:/x`, `/c/x`, a case change). New code compares paths only after `canon_path_key` (`tools/platform-lib.sh`; the contract and its sources are in `docs/research-path-and-rule-standards.md`), never as raw text; existing comparisons are being moved onto it (t-c8c6 shell, t-9d04 Go). When both folders exist, compare file identity first (unverified on Git Bash: t-c8c6). Identity accepts spellings the string compare refused (a case variant), so a boundary that persists or keys on the path returns the folder's own spelling, never the caller's (t-9d04; class: identity-widens-spelling; id: P-110). Test any path comparison with the three spellings and a case change (the corpus `tests/fixtures/path-keys.tsv`, `tests/path-forms.sh`), reproduce a Windows-only symptom on the Mac with that corpus before fixing it, and name a finding class by the mistake (compared as text), never by the OS it was seen on (t-141a).
- **Git Bash path conversion:** an argument that looks like an absolute path is rewritten before a native exe sees it (`!/.tickets/` became `!C:/Program Files/Git/.tickets/`): set `MSYS_NO_PATHCONV=1` and `MSYS2_ARG_CONV_EXCL='*'` on that call and read the stored value back (t-edda; class: msys-path-conversion; id: P-109).
- **macOS:** bash 3.2 and BSD tools: `sed -i ''`, `date -j -f`, `stat -f`, `touch -t`; write portable forms with a GNU
  fallback (`date -u -d … 2>/dev/null || date -j -u -f …`). `wc -w` counts differently from GNU's (t-35a7).
  No bash 4+ syntax (`;;&`, `declare -A`, `${v,,}`, `mapfile`): the cloud container and CI run bash 5 and pass it, then it dies on the Mac. `source <(…)` loads nothing on 3.2 (use `eval "$(…)"`; `tests/shell-portability.sh` lints it): prefer a repo lint the cloud also runs over a reviewer's memory (t-0865, t-6cf5; class: bash32-only-trap-passes-cloud; id: P-010). A shell change graded in the cloud is unverified for macOS until the Mac suite runs (`t-7f5f`). A test that plants a break must see it applied: GNU-only `sed '0,/re/'` addresses plant nothing under BSD sed (use `1,/re/` when the first match is not on line 1), so assert the expected message is non-empty and a no-op plant fails loudly (`t-04f4`). `os.UserCacheDir` ignores `XDG_CACHE_HOME` on macOS (`~/Library/Caches`): derive an expected path from the same call, never from Linux's (`t-68ae`). `/etc`, `/var` and `/tmp` link into `/private`: a path check lists both spellings and tests the physical one, compares folders by inode (`[ a -ef b ]`, Go `EvalSymlinks`) never by string, and a ps command-line match tries the logical and the physical home. On Windows one folder is also `C:\x`, `C:/x` and `/c/x`, with either drive case: shell code compares with `canon_same_folder` (identity, then `canon_path_key`, tools/platform-lib.sh) and never writes a second copy of the drive rule (t-b2ff, t-50f7, t-dec4, t-134b, t-c8c6; class: path-alias-compare; id: P-027).
- **Linux:** GNU coreutils and bash 5; the reference for CI.
- **Claude cloud container:** Linux, running as root, so `chmod` cannot make a folder unwritable (point a test at a path
  under a regular file instead); set it up with `tkt cloud-env` (domains, setup script). It is no stand-in for a performance symptom: profile on the OS that shows it, with its real gitignored data (the cloud and a clone both measured 0 tickets) (`t-1699`, `t-3b90`).
- A size cap measures content bytes (`wc -c`, `find -type f` sizes), never `du`: its block counts differ by filesystem, so a cap that passes on APFS fails on the cloud's Linux (t-0d96).
- **macOS bash 3.2:** it cannot parse a quote inside a heredoc inside `$( )`; read the text with `read -r -d '' v <<'EOF'` instead (t-00e0; class: bash32-heredoc-in-subst; id: P-062).

## Go

- A server that follows a child's output reads fixed chunks, not lines: `bufio.Scanner` stops at its token limit and leaves the pipe full, so the child blocks and the job reads running forever. A stop must reach the whole process tree (Windows: `taskkill /T`; killing the `tkt.cmd` wrapper leaves bash running), and a per-key handle is cleared when a new run starts so a stop cannot hit the previous finished command (`t-d271`). A child moved into its own session (`Setsid`) leaves the terminal's Ctrl-C: the parent traps the signal and stops the child's group; kill a group, not one pid, when the child may have children (t-ada9, t-5157; class: child-escapes-signal-group; id: P-013).
- Go test with a background goroutine that writes into `t.TempDir()` → teardown waits on the WaitGroup it joins, or `go test` flakes on cleanup; a cached `ok` hides it, so reproduce with `-count=N` and read every failure message.
- Go ignores SIGALRM, so `perl -e 'alarm N; exec …'` cannot time-limit a Go binary: fork, then SIGKILL the child (`t-8020`). Any new file under a released Go module's folder, a `_test.go` included, changes its source key (`tools/src-key.sh`) and needs a new binary release: check it before committing, or keep the file outside the folder (`t-15d8`). A new Go package also joins `scripts/test.sh` `go_board` (or its tests never run) and the release suites' fixture repos (or src-key fails there) (t-0829; class: new-package-unregistered; id: P-111).
- A writer never produces what its own reader refuses (re-check the cap after `MarshalIndent`, before the rename); an atomic-write test holds a hard link across the write; a parser of a file others write refuses trailing data (`json.Decoder` stops after one value); a document is read whole under a cap, not tail-kept like a log (t-dba0, t-862e, t-3137; class: writer-reader-contract; id: P-037).
- `filepath.WalkDir` Lstats its root: a symlinked root measures as one non-regular entry (0 KB), so resolve the root first (`os.Stat`/`EvalSymlinks`). A `--json` mode answers JSON on every branch (not capped, not present, `--list`), or a caller that parses it gets text on exactly the edge case (t-19bb).
- Run `go test -race -count=3` on every changed package, since `-count=1` hides a race; a Go test that swaps package state (a cache) takes the same mutex and resets in-flight flags (t-761b).
- Errors: wrap with `%w`, start the string lowercase (a product name such as Copilot or Git keeps its capital with `//lint:ignore ST1005 <reason>`, t-9a2b), and either log or return an error, never both. Every goroutine has an exit (`ctx.Done()` or a closed channel), and only the sender closes a channel. A path under a root (doc tabs, ticket files, themes) opens through `os.Root`, not a Clean/EvalSymlinks check. A secret or token comes from `crypto/rand` and is compared with `subtle.ConstantTimeCompare` (adapted from samber/cc-skills-golang, MIT; t-ca0e).
- A new `internal/` package, or a new import between internal packages, adds its line to `allowedInternalImports` in `cmd/canon-go/importboundary_test.go` in the same diff; a port from tools/sprint or tools/tkt is its own package, never a file inside board or daemon (t-ca0e). The boundary guard lists the graph per GOOS (darwin, linux, windows) and reads `.TestImports`/`.XTestImports` too, since `go list` shows only the host's non-test imports (t-ca0e; class: import-guard-host-only; id: P-145).
- A write-deadline test removes the buffer (`net.Pipe`), never a loopback socket: a capped send buffer still let the kernel drip writes inside the deadline (green on the Mac, red on Linux CI) (t-1775; class: deadline-test-os-buffered; id: P-140).
- A folder name from a path the user typed takes `filepath.Abs` first: `filepath.Base(filepath.Clean("."))` is `.` (t-c2de; class: base-of-relative-path; id: P-144).
- A daemon that types into an agent session waits for output-quiet, never a hook-set status alone (`awaiting-input` stays set while the agent works), and a message telling the agent to end its turn matches every branch of what the daemon does next (t-3425; class: typed-into-working-session; id: P-112).
- `strconv.ParseFloat` accepts `Inf`, `NaN` and `1e308` within a short field: a number read from an untrusted log is checked with `math.IsInf`/`IsNaN` and bounded to a finite range before it is summed (t-9113; class: untrusted-float-unbounded; id: P-068).
