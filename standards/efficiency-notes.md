# Agent Standards: domain notes

On demand, not always loaded. `efficiency.md` (always loaded) keeps the rules every session needs and names these sections in one index line; read a section before working in its domain. Moved here from efficiency.md in t-8837 (2026-10-15), verbatim.

## Duplication exceptions

The always-on rules are "same fact in several files → one owner" and "a third copy → remove the duplication". These are their two exceptions, which `tests/doc-mirror-parity.sh` and `tests/gate-model-parity.sh` rely on.

- Same fact in multiple files → pick one owner, derive the rest. Exception: deliberately-mirrored docs/prose that must stay self-contained for separate consumers (e.g. gate docs each dispatched to a fresh subagent) — keep the copies, lock them with a parity test (`tests/doc-mirror-parity.sh`) instead of merging.
- A third copy of the same logic appears → remove the duplication, don't copy again. Exception: same logic ported across incompatible runtimes (bash/Python/Go, etc.) with no shared-code option — keep the ports, lock them with a parity test instead of merging.

## Shell strict mode and traps

- Under `set -euo pipefail`, `VAR=$(cmd)` exits silently if `cmd` fails — `|| fallback` on the next line never runs. Safe: `VAR=$(cmd) || VAR=fallback` on one line.
- Under `pipefail`, `! cmd | grep -q x` can pass *without checking*: `grep -q` exits at the first match and SIGPIPEs the writer, so the pipeline reports non-zero even though it matched, and `!` flips that to success. It only fires when the writer still has output buffered, so a small input hides it and a larger one makes it deterministic. The same holds for `awk '…{exit}'` and `head`: let the reader open the file (`awk … file`), and test with an input larger than the pipe buffer (`t-fef7`, `t-4718`). Safe: `[ "$(cmd | grep -c x)" -eq 0 ]` — keep it inline; hoisting it to `n=$(cmd | grep -c x)` hits the previous trigger, since `grep -c` exits 1 on *zero* matches. A positive `cmd | grep -q x` fails the same way at random under load, which is why the full test run failed suites that passed alone; `tests/pipefail-early-exit.sh` refuses any `| grep -q`, `| head`, `| awk '…exit'` or `| sed '…q'` written on one line in a shell file under tools/, scripts/ or tests/ (`t-bcb8`, `t-ad89`). The rule: a reader that stops early needs a writer whose output is always small and bounded; otherwise let the reader open the file, capture first and match with `grep -q … <<<"$v"`, count with an inline `grep -c`, or end the line `|| true` when the kept value is the reader's own. A bounded writer goes in `tests/pipefail-early-exit-allow.txt` with the reason (matched on the line's text; a row that matches nothing fails). Not caught: a pipe split across lines, `| xargs grep -q`, `grep -m1`. `tests/pipefail-rewrites.sh` proves the rewrites on input over 64 KB.
- A bare `[[ cond ]] && cmd` as a function's LAST statement returns the `[[ ]]` test's own exit status (1) whenever `cond` is false — under `set -e`, that silently aborts the *caller*, not just skips `cmd`. Easy to miss because the common/expected case (`cond` usually true) never triggers it — it only fires once the false branch becomes reachable, potentially long after the line was written. Safe: wrap in `if`/`fi`, or append `; return 0` / `|| true` after it.
- Anything a function sets inside `$(func)` (an array append, a recorded PID) dies with the subshell, so a later cleanup trap kills nothing. Guard such helpers with `[[ $BASH_SUBSHELL == 0 ]]` (bash 3.2 has no `BASHPID`).
- Shell scripts: a function called in a `||`/`&&`/`if` list runs with `set -e` off, so an unchecked `mv`/`chmod` inside it cannot abort; `mv newdir olddir` onto an existing directory nests; `$((08))` is invalid octal (use `10#$n`). Make temp files with `mktemp` outside the work tree (or gitignore them) and remove them with `trap … EXIT`, not by a call on only the branch you tested.
- A child started under `set -m` (its own process group, so an interrupt can stop all of it) no longer gets the terminal's hangup: trap HUP with INT and TERM. Under `set -e` a trap's last cleanup command can fail (killing an already-dead group) and end the trap before its message: end each cleanup with `|| true`. A script backgrounded from a non-interactive shell inherits SIGINT ignored, so test an interrupt with TERM (`t-bad4`).
- bash 3.2 (macOS): `"${arr[@]}"` on an empty array is an unbound-variable error under `set -u`; use `${arr[@]+"${arr[@]}"}` (`t-1465`). A bare false `[[ … ]]` under `set -e` does not exit there either, so an assert written that way never fails: write `[[ … ]] || fail "…"` (`t-b62a`). `bash -n a b c` checks only `a` (`t-2633`).
- Concurrent `printf >> file` writers tear lines over about 1 KB: append a shared log with one write per line (Go `O_APPEND`) or under a lock (`t-f182`). A flag parser that reads `${2:-}` takes a trailing bare `--tokens` as "not given": check `$# -ge 2` and fail (`t-5ef3`).
- `IFS=$'\t' read a b c` collapses empty fields (tab is IFS whitespace) and shifts the rest: map empty to a placeholder upstream (`jq` `// "-"`) and test for the one expected value (`== false`), never `!= true` (t-a463; class: ifs-whitespace-collapses-empty).
- A line added to a script's ending (a message, a next step) is checked on every exit: each `return`/`exit`, the bootstrap path included (t-5738; class: every-exit-path).

## Tests, guards and hermetic runs

- A test failing inside a block your diff touches is not automatically pre-existing/unrelated — diff its failing assertion and target string against the base commit byte-for-byte before excluding it from scope.
- Grade test-count/pass-rate claims (e.g. "121/121 pass") against the actual recomputed total from real command output, not the doc's own summary arithmetic — check specifically for a silently-omitted did-not-run set. Quote a timing only from a run that exited 0 with every suite run (`t-b792`); before cutting tests for speed, measure time per suite (`scripts/test.sh` prints it) and check each "duplicate" an inventory flags against the code, since most tested different behaviour (`t-dd2f`).
- A test asserts against a re-implementation of the logic under test → call the production function instead. A locally rebuilt sort key or a hand-copied constant list passes while the real thing is broken. The same holds for a gate: compare against the real writers' output (replay them), not a copy of their format (`t-52f0`). A check that normalises (indentation, order) cannot see a bug in that dimension: pair it with an exact check on what must not change, and mutate each (`t-565f`).
- A guard exercised only against inputs it already handles is unverified → feed it the cases it must *reject*. Include spellings it has not seen; a match inside a comment does not count. A guard over a list (triggers, patterns) is tested by deleting each entry in turn; a "nothing reads/uses X" scan is proven by planted readers in each spelling (`$ROOT/…`, a variable dir, a JS path) (`t-278d`, `t-0b14`). A "nothing left behind" check (process, file, port) must observe what can leak (record the pid and `kill -0` it): an `lsof` on a stub that never listens passes. Prove it with a mutant that leaks. An absence assertion (`toHaveCount(0)`, "no dialog appeared", "never sends X") is revert-proven: a poll can clear the thing for you, a process-name watch subtracts what is resident (CoreServicesUIAgent), and "never sends" needs a spy on the receiving page (t-a1ac, t-3488, t-2aed; class: vacuous-absence-assertion). A per-line exemption marker (`/* non-ticket */`) needs a mechanical reject, not trust: the lint fails a marked line that names the guarded thing, and its probes include a marker on a forbidden line and an unlisted spelling (`"t-" + Date.now()`) (`t-eb92`). On macOS `mktemp -d` with no template ignores `TMPDIR`, so a temp-file leak check that pins `TMPDIR` watches an empty directory: give the code a template (`mktemp -d "${TMPDIR:-/tmp}/x.XXXXXX"`). A self-checking guard prints the counter it keeps, never a hardcoded count (`t-b525`).
- A stub must evaluate its input the way the real tool does (a fake `python` that exits 1 on any code hides a dropped version test) and have a mode for each branch the code takes, the fallback included; a stub that returns already-processed output (a `gh` stub returning TSV) never runs the real query or `jq`, so back it with one live read-only run. A per-candidate timeout bounds the wait for one candidate only: two hanging candidates take twice as long (`t-a5f6`, `t-1465`, `t-4cd8`). In a PATH dir of symlinks to real tools, put stubs first and skip their names when linking: `cp` onto a link writes through it into the real binary (`t-90a3`). A stub that is a silent `exit 0` cannot prove a call or its order: record each call and assert the sequence (`t-2ea4`).
- Where PID 1 does not reap orphans (a Claude cloud container), `kill -0` answers alive for a zombie: count a zombie as dead (`ps -o stat=`), falling back to `kill -0` where `ps` has no `-o` (`t-90bc`). Code that runs in a sandbox is tested under the sandbox's limits: a Claude cloud session's GitHub proxy allows REST only, so cloud-side `gh` calls are `gh api` and the test stub refuses GraphQL and the network on that side (`t-35d2`).
- Writing a parser or a gate for an existing artifact family (reports, tickets, logs) → count the shapes across all real instances and read the producer's own template first; run it on a real instance, not only fixtures shaped like the parser. A filter that drops boilerplate must name the boilerplate, not whitelist one content shape (keeping only list items dropped table sections); a line filter over Markdown (`# `, `<!--`, `## `) tracks code fences and position, with one fence rule on both sides of a round trip. Test it against every section shape real files use (lists, tables, prose, fenced code), and test a reader with the writer's real output (`t-a059`, `t-8543`, `t-554c`). A second reader of a field reuses the first reader's normalisation (strip bold: `**YES**`) instead of parsing the raw word (`t-f13a`). A log reader counts what the log means (one run per `agent_id`), not lines, and reads each per-ticket file once (t-b874; class: log-reader-counts-lines).
- New security/validation/race guard → ship a test that fails when the guard is reverted, and run the revert. Two causes for one symptom → prove each fix necessary by reverting it alone, plus one end-to-end test through the real client path. A revert counts only if the mutant ran and failed on its own assertion (a mutant that exits on setup, such as no manifest or a fresh clone running 0 tests, is no kill: read the counts; mutate a measurement fixture before baselining with it) (t-d689, t-3741, t-4fbe; class: mutant-killed-by-setup); redundant layers mask a lone revert, so test each layer separately. Each reject fixture is otherwise valid (real hash, real ids) and breaks only the clause under test, so every clause has an input only it rejects; disable the siblings to prove one guard, and N claimed layers need N revert tests (t-4371, t-3741, t-2af0, t-2aed, t-c6bb; class: guard-masked-by-sibling-check). A mask or bit-test guard needs a fixture on each side (0750 and 0755, not only 0755), and platform-gated code is mutation-swept on each platform, since a sweep on one never reaches the other's branches (`t-68ae`). Run reverts only in a scratch copy, never on tracked files. A fixture equal to the default the code would produce anyway (mode 0600 from `mkstemp`) cannot fail on revert. A "no leak" test of an environment pin also asserts the values that must pass through (`GOMODCACHE`), not only the absence of the pinned ones (`t-eb40`). A race fix needs a stress loop (dozens of trials) plus a deterministic test that holds the lock; a read-then-append on a shared file is check-then-act, so lock the pair.
- A green run where something didn't run proves nothing → treat "command not found", a silent skip, an early exit hidden behind a `grep` filter, or a test file missing from the entrypoint as a failure.
- Git config leaks into tests → pin `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM` and `XDG_CONFIG_HOME`. Worktrees share one hooks directory, so a hook finds its checkout with `git rev-parse --show-toplevel`, never from its own path. Ignore a symlink without a trailing slash (`/x/` matches directories only). Pin `HOME`, `TMPDIR`, `XDG_*`, `CANON_HOME` and any variable a wrapper exports (`CANON_TICKETS_DIR` from `evidence.sh`) too, and reproduce a "passes only on my machine" test under `env -i` or `scripts/test-hermetic.sh`. A test of delete/kill code plants a canary in the pinned dirs. A test that runs git in a temp dir unsets `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`: a hook hands them down, and `GIT_DIR` only from a linked worktree; a hook cleans only the child it starts. A test that writes under its own root runs on a scratch copy with a canary (`t-1cfc`, `t-ce0b`, `t-65c9`). A fake `https://github.com/...` origin rewrites reads (`ls-remote`, `fetch`) as well as pushes, and `scripts/test.sh` exports `GIT_TERMINAL_PROMPT=0` (t-9791; class: test-reaches-real-network).
- A fixture named for a kind (a worktree, a CRLF file, a subfolder project) is a real one (`git worktree add`, not a plain folder); git-aware code is tested from a linked worktree and from a project subdirectory, and asks the caller's worktree, not the main checkout (`t-21f7`, `t-1b74`). Put the check in the command, not the UI, so the Terminal and the dialog cannot disagree (t-ced8; class: check-runs-in-wrong-checkout).
- Changing a test's expected value to match new code → name which user's answer changed; if it is the common case, it is a regression (`t-12f8`).
- A test wait that hits its deadline fails loudly rather than continuing, and a "no new flakes" criterion needs a run on the base commit first (`-race` was already red on main) (`t-67a6`). A narrowed or deferred browser run (cloud chromium only, no WebKit) leaves its criterion unproven, and a flake claim needs enough base and branch trials to tell the two apart (0/2 against 1/2 does not): the Mac full-spec run is the gate (`t-9a49`). Measure the cause before adding a retry or loosening a guard (31 of 31 retried stalls stalled again), and classify a baseline entry from its logged error, not its test title (`t-8627`). A failure that also fails on the base or on every dev checkout is a dependence (real data, root, an unscoped selector), not a flake: read its message and ask the environment before baselining it (t-cca5, t-432d, t-6fb8, t-d0a5; class: misdiagnosed-flake).
- Write assertions that can see the bug: a command that publishes is checked against the source of truth (origin's merged head), not the local copy; a captured exit code is asserted with the output; an event test asserts right after the transition that must cause it, and that the event is absent before (`t-24b1`, `t-1cf5`, `t-8854`). Choose inputs where the broken answer differs from the right one: ids that sort differently from the order under test, a stale cached value unlike the fresh one (the cache key names everything the value depends on), a look-alike name and a mode-only change for an allow-list, a width where the share exceeds the cap; a refusal test checks the body and that no file changed, not only the status (t-a5c9, t-7456, t-75f5, t-1bd5, t-0ef2; class: fixture-cannot-distinguish-mutant).
- A test that locks wording anchors each phrase to the line that prints it (echo, die, throw), not help text or comments, and asserts every clause, verb and condition included; a mutant removes or flips exactly one fact (`t-153f`, `t-ce0b`, `t-1cf4`).
- A new ignore rule for a path that may already be tracked: `git rm --cached` it, and add a check that fails when a tracked path matches (`git ls-files -ci --exclude-standard`) (`t-fc00`).
- A test that reads source text (greps a file for a branch, slices a page between two literal lines, counts colours per file) is a reader of that text: grep `tests/` before replacing or moving a line, scope the search to the handler it guards with comments stripped, and count the real thing (`len(actions) == 0`), not a typed copy of today's 8 (t-6aaf, t-bb1b, t-be64; class: source-grep-test-fragility).
- Tests that copy a fixed list of files or tools into a fake install break when a launcher sources a new sibling or a tool joins `tools/`: give the list one owner in `tests/helpers.sh`, or grep `tests/` for copies before adding a file the launcher loads (t-b2ff, t-187e; class: fixed-file-list-in-test-fixture).
- A runner that globs its output folder for reports clears it first or refuses a non-empty one: a reused `--out` kept an earlier run's reports for the guard to judge (t-43a2; class: stale-output-dir).

## Security checks and gates

- A hostile-input test must match the sink's context: escaped text in `title="…"` needs a quote-breakout payload (`a"onmouseover="x`), not just `<img onerror>`.
- Widening what a security check allows → re-validate the new value at the point of use; never lean on an earlier check you haven't read, especially for files an agent can write (`.tickets/`). A flag that supplies a fact (`--pr N`) still passes the check that fact stood for (the ticket was imported): the check reads the ticket, not the flag. An allow-list of names admits by name only, so also check the type (a symlink under an allowed name), scope it to the one subject (`.tickets/<id>/`), and refuse dotfile parts (`t-c259`, `t-fdb1`). A check made only when data is saved does not protect a later reader: re-check at the point of use (an API key must not go to a hand-edited source host), and a load, slow call, save handler re-loads before the write or it overwrites changes made meanwhile (`t-d40b`).
- A new check that verifies what an older gate accepts must read every line the gate reads (every `^pass:`, not `head -1`), or an extra line walks past it.
- A guard that fails closed then falls through → check what the fall-through *writes*: a transient error (git, network) must not overwrite the state the guard protects. Pin it with a file-content assertion.
- An error must not become a normal-looking result: a failed read is not "absent", a failed `git` call is not "not a repo", and `curl` without `-f` prints an error page as output. Match the one error you expect; let every other one fail.
- Text from a clone, an issue or a pushed branch is untrusted input to a local command: validate any id before building a path from it, refuse to write through symlinks under the target, and check repo visibility before pushing notes. When a filter admits untrusted input (a label), take the admission fact and the content from one read: a label check then a second body fetch is a TOCTOU gap. A new reader of PR content checks fork origin before it fetches, and asks the same repo it fetches from (the ticket's `github:` repo, not `origin`) (t-07b5; class: untrusted-pr-head-read). Strip C0, DEL and UTF-8 C1 control bytes from anything echoed (`t-554c`, `t-4cd8`). Refuse input a parser could misread (a log name `z exit=0 y.log`) rather than parsing around it (`t-a3d7`). A message handler ignores a malformed value; it never coerces it to a default (t-7456; class: handler-coerces-malformed-input).
- Running a project's tests on a PR is running the PR's code: ask before it, and take the test command from the base branch so the PR cannot switch its own gate off. For an irreversible action, re-check the outcome on failure (`gh` can error after GitHub merged) (`t-4718`). Write the record of an irreversible action right after it, before any step that can fail under `set -e`: moving the write later makes every unguarded command in between a way to lose it (t-41ff; class: set-e-skips-post-irreversible-write).
- A pin covers only the file it names: the docs it loads read other paths, and `claude -p` still loads the PR checkout's own `.claude/settings.json`, `CLAUDE.md` and `.claude/skills/`. List what the pinned file loads before calling the PR's code pinned (`t-89b0`).
- Granting `git diff` or `git log` under dontAsk lets `--output=<file>` (and abbreviations such as `--outp=`) write any file: grant read-only git only through `tools/git-read`, and grep the tree for any other plain `Bash(git diff:*)` grant (`t-5ff5`; detail in `docs/headless-ci.md`).
- A new gate rule that names a finding states its condition next to the rule and is reconciled with the gate's exclusion and scope sections (`## Do Not Flag`, `## Scope` in `skills/wrapup/gates/security-review.md`) in the same edit: a rule naming unpinned actions as a finding collided with that gate's own "no hardening" exclusion (`t-fcb3`).
- Put a gate where every route passes (a hook), not in one command, and list the routes around it (push by URL, a child that reads the hook's stdin). A guard that cannot run (script missing, older checkout) refuses, and it judges the commit being published, not the working tree (`t-4ea4`, `t-b6b6`).
- Before tightening a shared escaper, list callers that escape a whole document and then parse it (`md()`'s image pass), and decode what they extract; a "none left" sweep searches the whole pattern, not only the same-expression form (`t-d2e1`). Filter the parsed result (`md()`'s output in an inert `<template>`), not its source or an output regex: transforms in between bypass both (t-c6bb; class: sanitize-at-wrong-layer).
- Before publishing, look at every image (blurs leak a private tab); a guard that bans a string builds it from parts, so the guard file does not reintroduce it (`t-afe2`).
- File names from a list, a PR or a user reach git as pathspecs: pass `--literal-pathspecs` (or `:(literal)`) to `add`, `checkout` and `rm`, and check no parent folder is a symlink before deleting (t-32f9, t-41ff; class: git-pathspec-from-data).
- Docs and acceptance state a mechanism's limit (a keyless chain detects a changed middle line, not a removed newest one) and claim "verified" only for what was run (t-3137, t-3488; class: security-claim-overstated).
- An audit line records only what the emitter can know: leave `actor` absent on a route a local script can drive (token-free, or empty Origin accepted), and let the viewer say unknown (t-4c09; class: audit-log-overclaims-actor).

## Destructive commands and user files

- Async lookup before a destructive action → after the `await`, re-check every precondition (identity, status, liveness), not just the one you guarded; test it by gating the request.
- Command that deletes data or stops processes → its "nothing unsaved" guard lists everywhere git keeps work (dirty tree, unpushed commits on every branch, stash, linked worktrees, skip-worktree edits) and probes each; it refuses when run inside the process it would stop; a prompt between probe and signal is an `await`, so re-verify identity at the signal. Test every rejected spelling.
- Before an irreversible delete, check the keep-rule against the shapes real data uses (docs cite evidence as a folder or a wildcard, not only a path): a dry run that shares the real run's rule cannot reveal that rule's gaps. A "nothing else was lost" claim comes from checking every affected item, not from one search pattern (`t-2fb6`).
- Editing a user-owned structured file (JSON/TOML) with `sed`/`awk` → guard the invariant, not the patterns: a signature of everything outside the edited member plus a validity check, and restore the original on any difference. A managed-block edit (BEGIN/END markers) changes only lines between them, matches the markers with a trailing `\r` stripped, and says "added" only when the file changed; its tests include a user line outside the block and a CRLF file (`t-5c4b`). A prune outside the markers recognises only canon's own exact lines, never a pattern (`@*/standards/*.md`) that a user's import also matches (t-351c; class: prune-matches-user-lookalike).
- Never `pkill`/`kill` by matching a process name, script path, or command-line pattern shared with anything the user might independently be running (a dev server, an agent daemon, a shared script invoked from elsewhere) — a pattern match can hit the user's own live, unrelated process and kill in-progress work with no undo. Resolve the exact PID first (a lockfile/state-file's recorded PID, the port a service publishes, or `$!` from a process this session itself started) and kill only that PID.
- A list that feeds a delete never emits a path built from an empty substitution (a failed `cygpath` turned `$(cygpath -u …)/canon-cockpit` into `/canon-cockpit`): skip the entry when the conversion fails, and test that failure (t-4872; class: empty-substitution-in-delete-path).

## Renames and doc sweeps

- Moving, changing the contract of, retiring or renaming a file or mechanism → sweep every doc surface by concept and paraphrase (cross-references, anchors, README prose, other skills), not only the known phrase; an exact-phrase grep proves only known spots; for a "nothing else" or "already in docs" claim, state the search scope and run it unrestricted (`git grep`, no file-type globs) and recompute counts. A rename by string also hits identifiers that only share the prefix: classify each hit, list the kept ones in `acceptance.md`, and exclude exactly that list from the evidence grep. A doc claim about a UI or a tool's flow is checked against the surface the reader sees (render it) and the tool's own printed next step (`t-e6d2`). An inventory of "every way X happens" searches by capability (every way a process or remote session starts) and names its patterns in the file (t-d42a); review a global `sed` per touched file (t-0aa7; class: inventory-by-pattern-incomplete).
- Before renaming a field to match a plan, read what its published contract promises (`docs/plugins.md`: v1 only gains fields); add the new thing as an optional field instead (t-15b5; class: breaks-published-contract).

## Cross-backend parity

- Cross-backend equality: parse JSON before comparing (`json.dumps` vs `json.Marshal` differ in whitespace); compare bytes only for files. Aim parity fixtures at text edges (trim sets, lone surrogates, invalid UTF-8). For a user-edited file also use valid-but-wrong shapes (`null`, array, scalar), and CR/CRLF: run one hostile line through both ports (bash stripped every CR, PowerShell only trailing ones). A rule that must hold in N implementations or N lists gets one case table run through all of them, each fixture bare for the case under test (a home with `.git` hid a started-in-home bug); two sides naming one folder derive it from the same call, and a guard that byte-compares a writer's output runs under the setting that changes bytes (`core.autocrlf=true`) (t-dec4, t-5738, t-4872, t-b266, t-cb66; class: parallel-ports-drift).

## Platforms

canon runs on four: every session's AGENTS.md carries a one-line pointer here (tools/skills/agents.sh, t-5c4b).

- **Windows: Git Bash only.** canon's commands run in Git Bash, never PowerShell or cmd (a `.cmd` wrapper runs bash for you).
  The Bash tool is Git Bash: unquoted `C:\...` backslashes are escapes (and trip Claude Code's approval prompt). Use forward-slash (`/c/Users/...`) or quoted paths. A suite that has only run on macOS hides host assumptions (real `uname`, `python3`): tests that model a platform stub it (`uname`, `cygpath`), and a skip must be loud. Git Bash spells one directory two ways (`/tmp/x` vs `C:/…/x`): never compare a shell path with a git path or `gitdir:` pointer as strings; use `git rev-parse --show-prefix` and test with a stub that spells it the Windows way.
- **macOS:** bash 3.2 and BSD tools: `sed -i ''`, `date -j -f`, `stat -f`, `touch -t`; write portable forms with a GNU
  fallback (`date -u -d … 2>/dev/null || date -j -u -f …`). `wc -w` counts differently from GNU's (t-35a7).
  No bash 4+ syntax (`;;&`, `declare -A`, `${v,,}`, `mapfile`): the cloud container and CI run bash 5 and pass it, then it dies on the Mac. `source <(…)` loads nothing on 3.2 (use `eval "$(…)"`; `tests/shell-portability.sh` lints it): prefer a repo lint the cloud also runs over a reviewer's memory (t-0865, t-6cf5; class: bash32-only-trap-passes-cloud). A shell change graded in the cloud is unverified for macOS until the Mac suite runs (`t-7f5f`). A test that plants a break must see it applied: GNU-only `sed '0,/re/'` addresses plant nothing under BSD sed (use `1,/re/` when the first match is not on line 1), so assert the expected message is non-empty and a no-op plant fails loudly (`t-04f4`). `os.UserCacheDir` ignores `XDG_CACHE_HOME` on macOS (`~/Library/Caches`): derive an expected path from the same call, never from Linux's (`t-68ae`). `/etc`, `/var` and `/tmp` link into `/private`: a path check lists both spellings and tests the physical one, compares folders by inode (`[ a -ef b ]`, Go `EvalSymlinks`) never by string, and a ps command-line match tries the logical and the physical home (t-b2ff, t-50f7, t-dec4; class: path-alias-compare).
- **Linux:** GNU coreutils and bash 5; the reference for CI.
- **Claude cloud container:** Linux, running as root, so `chmod` cannot make a folder unwritable (point a test at a path
  under a regular file instead); set it up with `tkt cloud-env` (domains, setup script). It is no stand-in for a performance symptom: profile on the OS that shows it, with its real gitignored data (the cloud and a clone both measured 0 tickets) (`t-1699`, `t-3b90`).

## Go

- A server that follows a child's output reads fixed chunks, not lines: `bufio.Scanner` stops at its token limit and leaves the pipe full, so the child blocks and the job reads running forever. A stop must reach the whole process tree (Windows: `taskkill /T`; killing the `tkt.cmd` wrapper leaves bash running), and a per-key handle is cleared when a new run starts so a stop cannot hit the previous finished command (`t-d271`). A child moved into its own session (`Setsid`) leaves the terminal's Ctrl-C: the parent traps the signal and stops the child's group; kill a group, not one pid (t-ada9, t-5157; class: child-escapes-signal-group).
- Go test with a background goroutine that writes into `t.TempDir()` → teardown waits on the WaitGroup it joins, or `go test` flakes on cleanup; a cached `ok` hides it, so reproduce with `-count=N` and read every failure message.
- Go ignores SIGALRM, so `perl -e 'alarm N; exec …'` cannot time-limit a Go binary: fork, then SIGKILL the child (`t-8020`). Any new file under a released Go module's folder, a `_test.go` included, changes its source key (`tools/src-key.sh`) and needs a new binary release: check it before committing, or keep the file outside the folder (`t-15d8`).
- A writer never produces what its own reader refuses (re-check the cap after `MarshalIndent`, before the rename); an atomic-write test holds a hard link across the write; a parser of a file others write refuses trailing data (`json.Decoder` stops after one value); a document is read whole under a cap, not tail-kept like a log (t-dba0, t-862e, t-3137; class: writer-reader-contract).
