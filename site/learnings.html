Learnings

Lessons that earn their place in your next session.

Canon turns what a fresh reviewer finds in a sprint into rules your agent starts with next time. A different agent judges which ones are worth keeping, and you make the final call.

How a finding becomes a rule

Capture automatically. Promote deliberately.

The first three steps run every time a sprint closes. Nothing becomes a standing rule until a fresh reader recommends it and you agree.

at sprint closeAutomatic, no extra command
  1. Capture
  2. reviewer

    A fresh agent with no build history reads the diff and writes review-notes.md. Advisory, not blocking.

  3. tkt learn

    Step 8 of sprint complete writes .tickets/<id>/learnings.md from deviations, evaluator findings and reviewer findings. Status UNPROMOTED. A clean sprint writes nothing.

  4. learnings-sweep

    The agent compresses one row into the root LEARNINGS.md index. A protocol step, never a close gate. The file is an unreviewed queue and is not imported.

later, fresh sessionJudged by someone who was not there
  1. Judge
  2. promote-learningsreport only

    Reads every UNPROMOTED row and its source file in full. Asks whether a different future sprint would hit the same mistake.

  3. one destination

    Each durable lesson gets exactly one proposed home. Each one-off gets a recommendation to dismiss, with a reason.

  4. no self-promotion

    The sprint that produced a lesson never promotes it. Everything looks load-bearing to the agent that lived through it.

your callA human decides
  1. Decide
  2. apply

    In canon, you write the rule by hand and flip the row to promoted or dismissed. In a project, /promote-learnings asks which proposals to write.

  3. Use
  4. next sessionloaded

    Promoted rules arrive through files a session already loads, so nobody has to recall the incident.

Where a lesson goes

The narrowest home that is read at the right moment.

A rule that is always loaded costs tokens on every turn. Ask when a future session would make the mistake, then pick the smallest place read at that point.

In your own project

Your project gets its own PROMOTED.md.

Canon's standards/ and skill references belong to canon, so a project never writes into them. It keeps its own destination instead.

One file, one import.

skills.sh add sprint creates PROMOTED.md at the project root and adds @PROMOTED.md to AGENTS.md. Claude Code loads it every session. skills.sh refresh covers projects that added the skill earlier.

Unreviewed stays unloaded.

LEARNINGS.md is never imported. Loading it every session would skip the fresh-reader judgment this flow exists for.

You confirm every line.

Run /promote-learnings in an interactive session. After the report it asks which proposals to apply, writes only those to PROMOTED.md with the ticket ID, and flips each row to promoted → PROMOTED.md.

The Upkeep card reports, never writes.

It runs the same skill headlessly and stays report-only. Its ? panel points to the interactive step. Keep PROMOTED.md short: the skill warns when entries pass 60 lines.
